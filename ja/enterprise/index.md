# 導入資料の一覧

Dagu の導入を検討する SIer と情報システム部門のための資料です。稟議、要件定義、設計書、受入試験の下書きとしてそのまま使えます。

| 資料 | 使う場面 |
| --- | --- |
| [非機能要求グレード対応表](./non-functional-requirements) | 要件定義で、Dagu が対応する範囲と利用者が用意する範囲を切り分ける |
| [構成例](./architectures) | 単一ノード、二重化、分散から構成を選ぶ |
| [パラメータシート](./parameter-sheet) | 設定値を設計書として残す |

| [セキュリティチェックシート回答例](./security-checksheet) | 顧客や社内のチェックシートに回答する |
| [PoC 手順](./poc) | 本番採用の前に、自社環境で確認する |

## 導入前に確認していただきたいこと

- **サポート:** 修正が提供されるのは最新の安定版のみで、長期サポート (LTS) はありません。Team と Pro のライセンスにサポートは含まれません。応答目標を伴うサポートは Enterprise 契約で提供します。詳しくは[サポート方針](/ja/server-admin/support-policy)を参照してください。
- **二重化:** アクティブ/スタンバイ構成には、利用者が用意する共有ストレージが必要です。障害が起きたホストで実行中だったジョブは失敗扱いとなり、途中から再開はしません。詳しくは[高可用性](/ja/server-admin/deployment/high-availability)を参照してください。
- **権限:** ロールはサーバー全体またはワークスペース単位で割り当てます。ジョブ単位のアクセス制御はありません。
- **移行:** 既存製品の定義を自動で変換するツールはありません。
- **閉域網:** 期限超過や開始遅れの通知は Dagu Console の機能のため、閉域網では使えません。代わりの方法は[閉域網](/ja/server-admin/deployment/closed-network#alerts-without-dagu-console)を参照してください。
